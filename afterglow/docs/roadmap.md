# 音乐播放器迭代计划

按可验收的功能分阶段推进。每阶段完成可用功能并验证，再进入下一阶段。第一版已实现本地与远端直链播放、音乐库、收藏、队列和本机保存；同时完成歌单、专辑、元数据读取与 LRC 同步的初版。下一步依据实际使用反馈完善兼容性、长列表性能和数据导入导出。

## 第一阶段 可用的播放器

### 1 工程和播放内核

建立 React 与 TypeScript 工程、样式变量和响应式布局；实现曲目类型、单实例播放内核及两种音源适配器。

验收：本地选择一首音频和添加一个有效的远端音频地址后，分别能够播放、暂停、拖动进度和调节音量。失败链接显示错误且可替换或重试。连续快速切歌不会播放过期请求对应的歌曲。

### 2 音乐库和播放队列

实现多选与拖放、搜索、队列增删、上一首、下一首、顺序播放、单曲循环和随机播放。提供空状态、加载状态和移动端播放栏。

验收：单曲自然结束后的行为与播放模式一致；随机上一首遵循历史；删除当前曲目和清空队列行为明确；文件名包含特殊字符时正常显示。

### 3 本机保存和第一版交付

加入 IndexedDB 仓储、收藏、偏好保存和刷新恢复。远端链接提供是否保存的选择，本地文件刷新后提示重新选择。补齐键盘操作、移动端布局和使用说明。

验收：刷新后已保存的远端曲目、收藏和音量恢复，页面不自动播放；本地失效文件有可操作提示；数据库不可用时仍可临时听歌。通过桌面与窄屏浏览器检查后发布第一版。

## 第二阶段 改善收藏与听歌体验

依次增加自建歌单、标签与封面读取、LRC 歌词、排序与筛选、队列和歌单导入导出。先确定字段和交换格式，再实现导入校验及版本兼容。

验收：一首曲目可进入多个歌单；删除歌单不会误删其他歌单中的曲目；歌词跟随播放时间；导出的数据再次导入后曲目关系保持一致。

## 第三阶段 扩展音源和同步

根据真实需求选定一项再实施：指定服务的授权音源、个人远端音乐库、账号与跨设备同步，或 PWA 离线功能。涉及后端时独立增加 API 层，沿用现有音源接口与仓储接口。

验收由选定服务的接口能力、鉴权方式、数据范围和失败恢复策略共同确定。平台分享链接解析、云端代理和版权内容聚合不作为第一版隐含能力。

## 每次迭代的完成条件

- 用户路径真实可用，没有仅供展示的按钮。
- 类型检查与构建通过，受影响的核心逻辑验证通过。
- 完成加载、空列表、失败、刷新和窄屏状态检查。
- 涉及存储变更时包含迁移策略；涉及权限时说明实际数据流。
- 更新使用说明和架构决策，记录尚未支持的场景。
